# 120 FPS 渲染优化验证（2026-10-15）

保持 1440 × 810 内部画布（逻辑视口的 3 倍）、材质法线、动态光照、建筑动态、风雪及踩雪反馈。比赛逻辑仍使用固定 60 Hz 步长。

- Phaser 显式设置 `fps.limit: 0`，通过 requestAnimationFrame 跟随显示器刷新率；关闭时间步平滑，固定比赛逻辑自行累计真实帧间隔。右上角实时 FPS 按实际 `POST_RENDER` 次数统计，每 0.5 秒更新，切换页面可见性时重置采样。不启用 Phaser 的限帧器：该版本会清零累计时间，在 165 Hz 屏幕上设置 120 上限可能降至约 82.5 FPS。
- 远景轮廓和风雾的三角剖分缓存一次，使用相同的 Earcut 算法、轮廓点和透明度；风雾保留 32 个轮廓点和全部 22 × 3 层。
- 同帧风雾复用相同位置的风场采样；避免重复切换已经生效的 Light2D 管线。

## 浏览器测量

本机 Chrome、RTX 3060 / ANGLE D3D11。测试通过浏览器路由临时恢复旧版轮廓绘制，进行同场景对比，不回滚工作区文件。每组手动推进 100 个 120 Hz 渲染步，去掉前 30 帧预热，记录完整场景更新和 WebGL 提交耗时；每帧调用 `gl.finish()`。全部画质开关开启。

| 场景 | 原绘制平均 / P95 | 优化后平均 / P95 |
| --- | --- | --- |
| 出生区域 | 1.63 / 2.40 ms | 1.13 / 1.70 ms |
| 推进约 120 秒后的中路，48 个实体 | 2.17 / 2.70 ms | 1.95 / 2.60 ms |

两组场景均低于 120 FPS 的 8.33 ms 单帧处理预算。1600 × 1000 浏览器截图对比：出生区域与中路各组前后差异均为 **0 像素**。

这些数据是受控浏览器渲染处理耗时，不是前台显示器实际呈现帧率或长时间整局稳定性证明。实际呈现帧率还受浏览器调度、刷新率、窗口可见性和其他程序负载影响；高刷新率屏幕允许高于 120 FPS。

TypeScript 检查、生产构建和现有 384 项测试通过。
