## 路线选择

**后续方向更新（2026-10-16）：环境以真实3D结构搭建。** 用户指出围栏/桥柱贴图感明显，要求三维体积；中央样板已落实[实体结构版本](visual-validation/2026-10-16/central-polish-03/README.md)。下文原有“建筑/桥体立面固定平面”方案保留为历史，不继续用于主要建筑轮廓。材质纹理与薄覆盖层可保留，角色暂继续使用已有像素动画。

以Three.js承载固定视角的2.5D美术场景：高质量像素地表、分层建筑与桥体美术、少量必要三维结构、现有角色动画与战斗表现。当前全部依赖程序几何及少量重复纹理的路线，仅保留为空间/玩法验证基础；继续增加几何细节不作为追近目标图的主方法。

两种资产坐标不能混用：地表源图按地面平面绘制，进入XZ平面后由相机投影；建筑/桥体立面按正式相机绘制，以固定平面和独立脚底/遮挡锚点接入。已经画好透视的整张目标图不能再当作平面地表投影一次。小样先解决这种对应关系，再量产。

正交相机保留平移和受控缩放；正式美术仅对一个校准后的主俯角负责。45/60/75度仍可用于灰盒诊断，但单视角建筑图不能承诺在任意俯角都正确。主俯角、角色屏幕尺寸和逻辑渲染分辨率需先用小样定下，不能从2048×1152概念稿直接推断。

## 拆分方式

| 层 | 生产资产 | Three.js内的职责 |
| --- | --- | --- |
| 地表底层 | 大石板变体、小砖修补块、破损/露底块 | 原生地表UV与模块拼接；多变体避免整图循环母题 |
| 地表覆盖 | 刻纹残片、薄冰、碎霜、雪边、内外角与零散雪斑 | 带透明边缘的过渡图集与连续区域遮罩；按地貌逻辑放置，不随机撒方块 |
| 桥边/立面 | 栏墙直段、转接、缺口、柱、桥拱和支撑立面 | 按统一接缝和锚点搭建；前后景分层，与地表边缘对齐 |
| 建筑/装饰 | 战斗防御塔、冰晶、石雕、火盆、碎石、冰柱 | 透明素材与必要简单几何混合；独立遮挡体/深度规则，不把整片建筑当无厚度贴纸随相机旋转 |
| 深渊远景 | 峭壁、远桥、雾谷等独立背景层 | 放在可走场景之后，以低对比和受控视差建立纵深 |
| 动态 | 火焰、飘雪、晶体微光、角色、技能 | 独立动画与事件驱动，匹配模拟时钟；技能不恢复照地光 |

原图中的建筑背后、底部和重叠区域没有完整信息，不能直接无损抠出全套资源。通过game-assets参考已认可图重新生成可拆分素材；模板路径按技能规范选型，通用生成用于构图自由的候选。每次检查实际像素网格、透明边、完整轮廓、方向、锚点与尺寸，不能以“生成成功”替代采用检查。

平面地表不能预烘进建筑和完整长投影；立面/建筑的绘制光照与实时光照要明确分工。保留绘制质感的材质配合克制的环境染色、接触阴影与火盆动态，不将带明暗的图片再强受光一次，避免双重阴影和色彩压暗。

## 首个可操作交付：中央桥段一屏

1. **定相机与资源契约。** 以中央桥段目标图为主，选一段包含主路、雪边、栏墙和桥下纵深的连续区域。用现有角色作比例尺，确认材质像素密度、通行宽度、固定俯角与渲染分辨率。任何尺寸先是候选，实机确认后冻结。
2. **生成一套相互配套的最小资产。** 先做地表底块与少量变体、石面→薄冰→积雪的边/角/内凹过渡、栏墙直段/缺口/柱、桥拱立面及远景。给每个部件记录源目标图、像素尺寸、世界占地、锚点、透明度和连接位置；不一次生成全图。
3. **接入真实比赛。** 通过独立地图美术定义引用资源和摆放，渲染器负责分层、深度、遮挡与释放，现有Bridge/Match负责碰撞、距离、伤害和时间。保留灰盒对照；不在绘图代码里新增玩法碰撞。
4. **先看一屏是否成立。** 将角色放入，实际移动、施放技能、靠近桥边、经过前景栏墙、平移/缩放、暂停和重开。确认脚底、接触阴影、拾取位置、透明排序、素材接缝和战斗可读性，再比较与目标图的材质/构图差距。
5. **达到质量后沿桥延展。** 小样通过才继续完成蓝方外塔至中央整个S01；新塔单独制作攻击结构与受损/摧毁状态。出生区图作为后续同风格基准，当前不扩大可玩全图。

小样输出必须是原游戏内可操作场景，包含实际角色和技能；生成的效果图、静态整图背景、离线合成均不能单独满足此交付。
