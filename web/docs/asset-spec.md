## 八向迈步姿势样稿

已生成亚索、阿狸、盖伦各 8 张透明 PNG，以及各自的 3 × 3 方向预览图，保存在 `assets/hero-walk-directions/2026-10-09/v1/`。这是每方向 1 张迈步静帧，不是循环走路动画，未替换正式对局单位。亚索输出格为 128 × 128，阿狸和盖伦为 256 × 256；人物像素密度和实际脚底锚点仍需统一，不能视为原定 32 × 32 游戏精灵已完成。

方向命名对应屏幕坐标：`right = E`、`iso_front_right = SE`、`front = S`、`iso_front_left = SW`、`left = W`、`iso_back_left = NW`、`back = N`、`iso_back_right = NE`。三套素材的左右、斜前、斜后三组均验证为镜像，会改变非对称护肩和持刀 / 持剑 / 持球手。亚索斜后方辨识度偏弱，阿狸背面尾巴遮挡较多，盖伦披风遮挡部分后腿；输出含软透明边缘，后续需验收。

游戏位置继续按归一化向量连续移动，朝向角用 `atan2(dy, dx)`；只有图片选择映射到最接近的八向。预览中的方向模块增加 4°切换容差，静止时保留朝向，并未改变对局移动逻辑。先修正并统一素材，再按每方向 4 帧制作循环，共每英雄 32 帧。

## 主方向待机与走路动画样稿

按用户确认的6条主方向方案，使用项目 game-assets Skill 的 `animate-run` 像素动画能力，为亚索、阿狸、盖伦分别生成右下 SE 待机和走路循环。资源保存在 `assets/hero-animations/2026-10-09/v1/`，沿用上一轮右下方迈步静帧，原输入文件不修改，不做缩放或再次像素化。当前仅有一个方向，不是完整八向动画，也未接入正式对局。

每条循环8帧，帧时长100毫秒，总时长0.8秒；WebP与GIF无限循环，透明度为0或255。每条同时输出一张3×3 PNG图集，按行读取前8格，第9格透明且不参与播放。亚索每帧128×128，图集384×384；阿狸和盖伦每帧256×256，图集768×768。共6条独立动画、48帧，18个最终媒体文件。积分消耗210，余额1515。

独立预览支持英雄切换、暂停、前后逐帧、0.5× / 1× / 2×播放、地图 / 透明棋盘背景、原始文件查看和下载。预览仅以整数最近邻放大，固定同一英雄两种动作的画布位置，不按每帧包围盒自动对齐，以免掩盖滑步。锚点是样稿检查用近似值，并非正式游戏脚底锚点。

仍需打磨：亚索头发、护肩和待机身体摆动；阿狸走路中段偏向正面的朝向漂移及尾巴轮廓变化；盖伦步幅较保守，披风和剑有少量形变。循环播放属性不等于首尾完全无缝，不据此宣布正式素材验收通过。确认样稿后再修正造型、实战尺寸和锚点，并扩展其余七向。

## 完整八向待机与走路样稿（本轮决定）

用户明确要求跳过美术修正、直接扩展八向。本轮沿用原有各方向静帧及像素动画设置，不重画、不缩放、不重新像素化，也不修正左右镜像与非对称装备。此决定替代上一阶段“先修正再扩展”的顺序。

亚索、阿狸、盖伦各有 E / SE / S / SW / W / NW / N / NE 八向，每方向待机与走路各一条，共48条独立动画、384帧。原有6条SE动画原样引用，其他七向新增42条，保存在 `assets/hero-animations/2026-10-09/v2/`。全部提供透明WebP、GIF与PNG图集，共144个最终媒体文件；引用的SE文件仍位于v1目录，不应单独搬走v2而遗漏v1。

规格保持每条8帧、每帧100毫秒、800毫秒循环；PNG为3×3图集，按行读取前8格，最后一格透明。亚索每帧128×128，阿狸与盖伦256×256；透明度0/255。原始源图SHA-256校验未变化。PNG与WebP逐帧可见像素一致；GIF因调色板有轻微色差，优先使用PNG或WebP。

开发服务器启动后，可直接访问 `/assets/hero-animations/2026-10-09/v2/index.html`。预览支持三英雄、八方向、待机/走路并排、暂停、逐帧、0.5×/1×/2×、地图/透明棋盘及原始文件下载。显示仍为亚索3×、阿狸与盖伦2×整数最近邻；固定检查锚点仅供样稿比较，未调整正式角色尺寸，也未接入对局。连续360°移动与八向图片选择是两个独立环节。

本轮余额11515→10045，净消耗1470积分。一个亚索朝上行走任务服务端失败，原任务恢复确认失败且35积分已全额退回后，仅补做该缺失动作；其他成功文件没有重生成。尺寸、帧数、透明度和循环元数据通过不等于正式美术验收，当前仍保留源造型与动作跳动。

## 亚索普通攻击单方向样稿

本轮聚焦亚索，未生成盖伦或其他方向普攻。参考[英雄联盟官方亚索英雄页](https://www.leagueoflegends.com/en-us/champions/yasuo/)的R演示约6.0–7.2秒近身连续挥刀，逐帧检查抬刀、身体扭转、接触与回收；Q演示的直线刺击用于区分技能动作。官方YouTube英雄介绍在当前环境要求登录验证，未声称观看该视频。实际使用的是官方页可访问的视频，动作观察转为提示词，不是直接输入视频的动作迁移，也不复刻大招、强化刀光或官方数值。

沿用原SE的128×128亚索素材，不缩放像素内容，添加左8、右40、上16、下32透明边距，得到176×176画布。先用game-assets `image-edit-run` 编辑肩后持刀的攻击起手，再以Pixel Advanced `animate-run` 生成一次右下方斜劈、回收的8帧动画。固定样稿检查锚点由原[64,115]对应到[72,131]，不按各帧包围盒重新对齐，也不修改原待机、走路或角色静帧。

输出在 `assets/hero-attacks/2026-10-09/yasuo/v1/`，最终普攻提供176×176透明WebP与GIF，以及528×528的3×3 PNG图集，前8格参与播放、最后一格透明。每帧100毫秒，原始动画无限循环；预览中的“播放一次普攻”在800毫秒后回到原角色，循环演示另有600毫秒间隔。时长只是预览参数，不代表正式攻速、伤害事件或攻击前摇；接入战斗状态机时需单独配置。

余额10045→9985，消耗60积分，起手编辑15、动画45，两任务成功，无重复提交。美术仍需验收：第3–4帧刀光偏宽亮，头发与刀形有变化，末帧与起手不严格一致。此版本为单方向动作样稿，不是完整八向普攻或正式对局资源。

## 亚索 A/B 普攻三组衔接样稿

用户要求多生成几组A/B衔接，本轮只做亚索右下SE的3组动作探索：斜劈/反撩、横斩/回斩、短劈/挑刀。每组独立A、B各8帧，共6条、48帧、18个最终动画媒体，输出在 `assets/hero-attacks/2026-10-09/yasuo/v2-ab/`。旧v1、现有八向待机/走路和正式对局逻辑均保留。三组是美术刀路设计候选，不是官方两套普通攻击的逐帧复刻。

按game-assets的复杂动作流程，先编辑低位与击中关键姿势，再用 `keyframes-run` Pixel模式。每条指定第0帧起手、第3帧击中、第7帧收刀；A从抬刀落到低位，B从同一低位回到同一抬刀。准备图保持176×176透明画布与原像素密度，检查锚点[72,131]。姿势编辑出现换手后，复用已生成的同侧抬刀姿势，并额外修补一张横斩姿势，不将不一致的旧肩后姿势用于动画端点。这一分支组内统一为画面右侧持刀；与现有待机持刀手的衔接仍需在正式接入前验收。

每条透明WebP/GIF为176×176、8帧、100毫秒/帧，总时长800毫秒；PNG为528×528的3×3图集，前8格有效，第9格透明。对比页固定2×整数最近邻，逐帧图1×，不移动、重采样或替换生成帧以掩盖跳动。连续A+B为1.6秒，不插入待机空档；单次播放停在B末帧。该时长只是样稿预览，不代表游戏攻速或命中时机。

8次姿势编辑各15积分、6次关键帧动画各45积分，余额9985→9595，实际消耗390积分。全部任务成功，无重复付费提交。动画端点姿势接近，但颜色和透明轮廓不完全相同，不是像素级无缝；第一组A中段刀光偏宽，第二组A/B刀路相近、脚部重心变化更大，第三组A刀光最克制但动作转折偏快。仍为美术样稿，不声明正式资源验收通过。

## 亚索连续左右横挥重新生成

用户否定三组旧样稿后，本轮改为一次生成完整左右横挥，不再拼接两个独立动画。资源位于 `assets/hero-attacks/2026-10-09/yasuo/v3-horizontal/`。起手图只增加透明边距并编辑持刀姿势，原角色像素内容未重采样；全部生成帧保持固定画布，未插值、镜像、重排、平移或裁剪来掩盖动作问题。

初次高帧率结果224×192、39帧、2秒，实际主要在两个姿势间跳变，部分左挥刀尖触边，明确不采用。第二次Pixel Advanced结果256×192、16帧、100毫秒/帧、1.6秒，提供透明WebP、GIF及1024×768的4×4 PNG图集，16格全部有效。全部透明度0/255，无空帧或触边；PNG与WebP可见像素一致。

第二次已有横向挥刀、手臂与腰肩转动，实际包含约两轮左右挥砍，并非精确两次命中的战斗动作。大面积白色刀光、护肩/服装细节变化和末帧到首帧的姿势跳变仍存在，尚未达到用户要求的流畅自然标准。只交付样稿供查看，不扩展八向、不修改盖伦、不接入对局。余额9595→9505，实际90积分：起手编辑15、未采用的初次动画30、第二次动画45，无重复提交。

## 亚索独立斜向 A/B 普攻

用户进一步明确刀路：A从画面右下挥到左上，B从左上挥回右下，是两次独立普通攻击，不是一条左右横挥循环。本轮回到衣着完整的原128×128亚索，增加左32、上48、右32、下16透明边距，得到192×192输入，像素不缩放。通过game-assets重新制作低位、高位和中间姿势，保留完整蓝围巾与银色护肩；不继承v3围巾丢失问题。

首尾帧控制分别生成A/B，各73帧、3秒。首次A实际抬刀下劈后再回到左上，方向错误，明确不采用；B保留为单次左上→右下斜砍。A补做胸前向左的中间姿势，用0/5/11三张关键图约束12帧右下→左上斜撩。中间静态输入整体左移22像素对齐脚底，不缩放、不裁掉可见像素；这是生成前输入定位，不是修改返回动画帧。

当前选用A12帧、100毫秒/帧、1.2秒，透明WebP/GIF和768×576的4×3 PNG图集，12格全部有效；B73帧、3秒，前7帧42毫秒、其余66帧41毫秒，透明和保留背景WebP。共5个选用的声明最终媒体，全部192×192；透明素材为0/255，无空帧或触边，A的PNG与WebP可见像素一致。

预览位于 `assets/hero-attacks/2026-10-09/yasuo/v4-diagonal-ab/`。A/B独立单次播放停在各自末帧；交替模式默认仅按播放速率统一每刀1.2秒，不改原文件、帧数、顺序或位置，也可切回原始制作时长。这不是正式游戏攻速或伤害时间配置。A已有指定斜撩刀路但中间过渡仍偏跳；B刀路正确但生成了大面积红色刀光，末段收刀停留较长；两处接缝仍有颜色、轮廓变化，未达到自然流畅定稿标准。衣着更稳定不代表所有细节逐像素不变。
