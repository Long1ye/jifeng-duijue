# 防御塔水晶悬浮

[连续实机与原版对照](http://127.0.0.1:5173/docs/visual-validation/2026-10-19/tower-float/motion.html) · [进入正常比赛](http://127.0.0.1:5173/three.html?map=howling&scene=match)

## 实现

红蓝各四座塔的水晶拆为独立层，塔身和前方石尖保持固定。几何遮罩使用现有 344×513 素材坐标，不按蓝色/红色筛选，因此白色晶面也会一起移动。塔身与其阴影通道同步移除原水晶，避免残留静态重影；原先被石尖遮住的晶面使用上方现有晶面作镜像延续，不将石头一起提起或留下三角缺口。

参数集中在 `TowerCrystal.ts`：局部抬升 14、上下幅度 5、周期 4.8 秒、横向轻摆 0.9。塔的整体缩放为 0.78，换算垂直移动范围约 7.02～14.82 世界单位，固定 45°、1600×900、正常缩放 0.6 下全程上下位移约 11 像素。各塔按位置错相；模拟时间相同，位置相同，重开无累计漂移。

保留晶面流光、红蓝颜色和攻击蓄能。晶光粒子使用独立水晶的世界坐标；浮动层同步塔身遮挡淡出和摧毁状态。抬高血条并扩展视觉塔冠选取高度，攻击距离、伤害和游戏碰撞参数不变。既有塔弹表现可从 `towerMuzzle()` 获取浮动核心的位置。

维护开关 `PaintedMapLandmarks.towerFloatEnabled`，默认开启；关闭恢复整张原图并隐藏浮动层，参数变化无须改图片。八个独立水晶最多增加八个可见绘制和八份小型几何，复用原有纹理，不增加渲染目标。水晶层不独立投影，以免每帧刷新整张场景阴影；塔身投影使用同步遮罩。

## 验证

- [浏览器专项报告](report.json)：八颗水晶移动而塔身固定；重复相同时间暂停冻结；开关恢复原图；外塔摧毁后隐藏核心；五次重开资源稳定。浏览器/shader 错误与失败项为空。当前镜头资源均为 108 个几何、31 张纹理，不能与不同镜头历史值直接比较。
- `blue.webm`、`red.webm` 为连续画布录制，显示 1600×900、内部 1920×1080、固定 45°、正常缩放 0.6；两段均完整播放到结束，时长约 4.75 秒。查看器可切换原版截图 `original.jpg`。
- 最高点实机检查：塔冠仍能选中对应蓝塔，血条下缘与水晶顶保留约 37.6 CSS 像素间距。
- 单测覆盖循环高度边界、暂停/重开、八座塔、共享纹理和攻击能量、开关、几何释放、遮罩与既有 shader 组合。全量 157 文件 852 项通过，TypeScript/Vite 构建通过。
- [战斗与音频回归](combat/browser-report.json)通过，浏览器错误、失败请求为空。

复现：开发服务 5173 下执行 `node scripts/validate-three-tower-float.mjs`。录制使用独立的真实 `Match`/`ThreeArena`，关闭 AI 和兵线以稳定观察；仅该录制页屏蔽 Vite 热更新，防止并行开发使测试场景重载。正式游戏不屏蔽热更新，也不使用这些调试布局。补充 UI 检查日志 `.cache/tower-float-ui.log`，构建与测试日志 `.cache/tower-float-*.log`。实现与技术验证完成，待试玩确认。
