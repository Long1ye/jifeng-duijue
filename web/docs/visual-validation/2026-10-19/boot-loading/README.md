# 首屏空白等待修复

## 原因

两个 HTML 入口在收到页面时立即用 `launcher-pending` 隐藏游戏内容，但开始菜单要等 `launch.ts` 及其静态依赖执行后才生成。启动脚本等待期间页面没有可见文字，表现为整片深色空窗。

## 修改

- `index.html` 与 `three.html` 内置启动面板、必要样式和故障处理脚本。收到 HTML 后即可显示品牌、启动状态与不定量进度条，无需等待外部脚本、样式或图片。
- 菜单可操作后移除启动面板；直接进入对局时，在游戏界面及资源加载面板挂载后移交显示。
- 开始菜单背景图改为异步加载，保持原素材与内容版本缓存，不阻挡菜单操作。
- 启动文件失败时显示刷新按钮；等待超过 8 秒时继续显示状态并开放手动刷新，不假装已经完成资源加载。

## 实际浏览器验证

`node scripts/validate-boot-loading.mjs http://127.0.0.1:5184` 通过，`npm run build` 通过。

- 修改前人为暂缓启动脚本：两个入口的可见正文都是空字符串，见 `before.json` 与 `before-*-entry.jpg`。
- 修改后在相同暂缓条件下：两个入口的启动提示均可见；脚本恢复后正常进入菜单并移除启动提示，见 `after.json` 与 `after-*-entry.jpg`。
- 暂缓菜单背景模块／图片：菜单仍可见且开始按钮可用。
- 暂缓 Three.js 游戏入口：直接进入模式仍显示启动面板，随后交接到游戏资源加载／大厅界面。
- 阻断启动脚本：显示失败提示及可用的刷新按钮。
- 正常路径浏览器运行时错误为零。

验证的是首屏反馈和加载阶段衔接；没有将页面下载、开发服务首次转换或大型资源加载的耗时宣称为消失。
