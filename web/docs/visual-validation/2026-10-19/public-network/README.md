# 公网联机预测、校正与弱网验证

本次完成公网部署前的客户端和传输优化，尚未部署公网服务器。服务器仍为房间权威：60 Hz 战斗模拟、20 Hz 状态广播。

## 本地移动预测与服务器校正

- 协议升级为 v3，状态携带蓝／红双方已处理指令序号 `ack`。服务器确认已消费的合法格式指令，包括战斗规则拒绝执行的操作，客户端丢弃已确认历史，仅重放未确认操作。
- `MovementPrediction` 使用最新权威英雄状态、平滑后的半 RTT 估计和本地输入时间重建导航；普通移动与停止立即呈现。与服务端共用 `walkUnit`，保持移速、减速、家园卫士、桥面边界和建筑绕行规则一致。
- 小位置误差以约 60 ms 时间常数衰减；超过 8 个世界单位的误差直接纠正。权威位置跳变超过 32、死亡、控制或技能动作时停止普通移动预测，不跨地图平滑瞬移。
- 攻击、攻击移动、技能和召唤师技能暂不预测；有这些未确认操作时，后续导航等待权威确认，避免猜测技能是否成功。伤害、生命、技能冷却和其他单位从不由预测修改。
- 断流最多预测到最新快照接收后的 250 ms，半 RTT 估计另有 150 ms 上限；暂停、重连、离开和换局清理预测。输入历史最多 128 条，溢出后等待对应指令确认再恢复预测。

## 插值与积压

- 对手、兵线和投射物继续用连续播放时钟插值。以近 100 个样本的到达迟滞 95 分位调整缓冲，范围 60–200 ms，增加较快、缩短较慢，不倒退播放时钟。
- 远端断流停在已知状态，不外推伤害或无限继续移动；积压超过 500 ms 的历史跳到近期状态，避免持续追赶过时画面。
- 断流期间内部播放时钟也停在最新已知状态；修复了仅画面停住、内部时钟继续前进导致重传恢复后一帧突然追赶的问题。持续移动弱网回归覆盖该情况。
- 每个连接独立保留一个可替换的未发送快照；发送积压超过 32 KiB 时合并后续状态，保留最新快照与指令确认。已经交给 TCP 的数据无法撤回。
- 战斗事件附带递增批次 ID 和原始模拟时间，合并状态时保留顺序，客户端按批次去重并在对应播放时间消费。长期后台期间过旧的表现音效仍会裁剪，最终战斗结果由完整状态恢复。
- 积压超过 256 KiB、待发送事件超过 256 KiB 或连续阻塞超过 2 秒时关闭慢连接，由已有暂停／重连机制恢复；快连接不等待慢连接。
- 客户端上传积压超过 16 KiB 时拒绝继续排入操作，并且不预测被拒绝的操作。

## 复测

```powershell
$env:PORT='5182'
npx tsx scripts/serve-network-validation.ts
```

另开终端：

```powershell
node scripts/validate-public-network.mjs http://127.0.0.1:5182
npm test -- --maxWorkers=4
npm run check:server
npm run build
```

客户端和服务器须同时使用 v3；已有对战服务需重启，两端刷新后再创建新房间。
独立验证服务关闭文件监听并使用专用 Vite 缓存，避免同一工作区其他开发任务触发热重载而打断计时。日常开发仍使用 `npm run dev:lan`。

## 验证边界

浏览器脚本运行两个独立 Chrome 上下文，经真实 WebSocket 连接真实对战服务；在应用消息交付层加入双向延迟、抖动及按序阻塞，模拟 TCP 重传影响。它不是操作系统级 IP 丢包测试：`lossEvery=100` 表示每 100 条消息注入一次 120 ms 阻塞，不能等同于真实网络 1% 数据包丢失。另有更频繁的阻塞压力档。

脚本测量双方本地操作响应、权威确认、停止后的坐标收敛、待确认输入数、插值缓冲和帧间隔；校验同一服务时间点的双方完整状态完全一致、短时交付中断后的恢复、刷新后原凭证与席位恢复及浏览器运行时错误。响应测量调用实际 `NetworkHost.command`，不包含物理鼠标和显示器扫描延迟。截图仅验证场景、HUD 与角色可见，不能单凭截图证明运动流畅。

发送积压的状态合并、事件保留、慢连接内存上限和快慢连接隔离由 `network-outbox.test.ts` 的可控队列测试验证。真实异地线路、跨运营商、长时间运行及多人房间容量仍需部署后实测。原始浏览器测量见 `report.json`。

## 最终结果

- 全量测试：171 个文件、931 项通过；服务端类型检查与正式构建通过。
- 网络专项：6 个文件、27 项通过，覆盖预测、确认重放、控制与暂停、输入溢出、事件去重、发送积压和按序弱网持续移动。
- 下表为同机两个独立浏览器上下文的短测，延迟列是配置的双向模型；响应是指令调用至角色位置首次变化。

| 配置 | 蓝方本地响应 | 红方本地响应 | 蓝／红权威确认 |
| --- | ---: | ---: | ---: |
| RTT 60 ms，抖动 5 ms | 0.9 ms | 4.2 ms | 89.4 / 67.5 ms |
| RTT 100 ms，抖动 30 ms | 2.4 ms | 6.6 ms | 157.7 / 162.2 ms |
| RTT 150 ms，每 100 条消息一次重传阻塞 | 8.3 ms | 0.8 ms | 193.5 / 240.6 ms |
| RTT 150 ms，每 20 条消息一次重传阻塞 | 2.5 ms | 0.5 ms | 199.9 / 155.6 ms |

关闭预测的同浏览器对照：位置首次变化为 309.4 ms，权威确认为 168.6 ms。这是一次条件相近的顺序对照，未声称两次网络调度完全相同。

所有档位停止后与权威位置误差小于 0.001 世界单位，待确认输入归零；双方同一模拟时间的完整状态一致；短时交付中断恢复、刷新后原席位恢复均通过；浏览器运行时错误为零。截图为 `blue-weak-network.jpg` 和 `red-weak-network.jpg`。

纯模型测试在每档 15.5 秒持续移动中验证：预热后停顿帧比例低于 3%，60 Hz 显示时单帧位移小于 2 世界单位，时间不倒退且不超出最新权威快照。该测试的理想线性移动不包含实际场景碰撞和渲染负载。
