# 局域网双人对战验证

## 房间码入口调整

- 从主菜单选择玩家对战后，先显示创建房间／输入六位房间码的独立大厅；加入成功前不创建游戏 canvas，不加载战斗场景。
- 加入成功后复用同一 WebSocket 和玩家席位加载游戏资源，保留双方准备、倒计时、共享对局和断线重连流程。
- 返回菜单或主动离开会退出房间；刷新页面保留重连凭证。
- 更新后的 `node scripts/validate-multiplayer.mjs` 已通过：验证加入前无 canvas、无效房间码留在大厅、两人同局、双方操作、共享状态和刷新重连，浏览器错误为零。`room-entry.jpg` 为独立大厅截图。
- `npm run build`、`npm run check:server` 通过；本次运行的 3 个联机测试文件共 9 项通过。

服务器：`npm run dev:lan`，默认端口 5180。页面入口：`/three.html?map=howling&scene=match&online=1`。

## 已验证

- Node.js 服务器复用 Match，以固定 60 Hz 模拟战斗，关闭英雄 AI，保留兵线、塔、技能和胜利规则。
- 两个独立浏览器上下文通过主机局域网 IP 创建／加入六位码房间，分别分配蓝方和红方，双方准备后倒计时开局。
- 实际浏览器输入可以分别控制双方移动和 Q；双方接收相同时间点的完整状态，兵线和两座可交战防御塔存在。
- 通过截图检查房间页面，以及双方出生区域、阵营提示、技能冷却和 HUD。
- Esc 和窗口失焦不暂停共享对局；刷新红方页面后恢复原房间凭证和席位。
- WebSocket 集成测试覆盖房间满员、版本错误、无效房间、非法凭证、指令合法性、绑定阵营、序号去重、暂停重连、重连超时、离开关闭、胜负同步及双方准备重开。
- 一血、首塔和 100 补刀结算保留；E 目标冷却按施法阵营隔离；快照能恢复成可供渲染查询的 Match 实例。

## 范围

本次在同一主机的两个独立浏览器上下文中验证，并经局域网 IP 访问服务；没有使用第二台实体电脑，因此跨设备防火墙和 Wi-Fi 隔离仍需现场验证。房间为内存状态，服务重启不保留；当前不含账号、排位、客户端预测或服务器按视野裁剪快照，适用于可信局域网好友对战。
